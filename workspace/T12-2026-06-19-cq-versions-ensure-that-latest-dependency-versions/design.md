# Design Discussion

## Current State

The project (`deadcode` 2.3.0) has **no runtime dependencies** —
`dependencies = []` (`pyproject.toml:21`). All third-party packages live in the
`test` optional-dependency extra: `hatch, ruff, mypy, pip-audit, deadcode,
pytest, pytest-cov, pytest-xdist, vupi` (`pyproject.toml:24-34`). None carry a
version specifier — every entry is a bare name (`research.md` Q1).

Actual version control lives in two generated artifacts, not in `pyproject.toml`:

- **`requirements-dev.txt`** — flat, fully `==`-pinned export with `# via`
  provenance, produced by `uv pip compile --all-extras` (`requirements-dev.txt:1-2`).
  This is the file every install actually consumes.
- **`requirements.txt`** — base-only compile; effectively empty (header only)
  because runtime deps are empty (`research.md` Q2).
- **`uv.lock`** — full uv lockfile (`version = 1`, `revision = 3`,
  `requires-python = ">=3.11"`) maintained in the tree but **never read** by any
  recipe in `Justfile`, `Makefile`, or CI (`research.md` Q3, Open Areas).

Regeneration is driven only by the **Makefile `compile` target**
(`Makefile:49-51`), which runs `uv pip compile -U` (`-U` = `--upgrade`, the
mechanism that pulls in latest versions). There is **no Justfile equivalent**
(`research.md` Q2). Installs go through `sync` (`uv pip sync requirements-dev.txt`
+ `uv pip install -e .[test]`) in both `Justfile:6-8` and `Makefile:45-47`.

Resolution source-of-record is a custom GitLab PyPI index
(`pyproject.toml:48-50`); artifacts still download from `files.pythonhosted.org`
(`research.md` Q4). CI (`.github/workflows/check.yml`) runs a matrix of Python
3.11–3.14 on `ubuntu-latest`, installs via `make .venv`, and runs `make check`
(= `test lint mypy audit deadcode`, `Makefile:5`). `requires-python = ">= 3.11"`
(`pyproject.toml:9`) and mypy is pinned to `python_version = "3.11"`
(`pyproject.toml:165`).

## Desired End State

`requirements-dev.txt` and `uv.lock` are regenerated so every pinned package
(direct and transitive) sits at its latest version compatible with
`requires-python >= 3.11`, the resolved set is internally consistent, and the
full check suite passes.

**Verification:**
1. `make compile` produces a diff bumping pins; `requirements.txt` stays
   header-only (no runtime deps).
2. `uv.lock` regenerated and consistent with the same resolution.
3. `make .venv && make check` passes locally (the exact CI path) — covers
   `pytest` (coverage ≥ 95%, `pyproject.toml:211`), `ruff`, `mypy`, `pip-audit`,
   `deadcode`.
4. No transitive package raises a `requires-python` floor above 3.11 (would break
   the 3.11 CI leg — `research.md` Q5). If one does, it must be constrained, not
   accepted.

## Patterns to Follow

- **Regenerate, never hand-edit pins.** Pinned files are autogenerated
  (`requirements-dev.txt:1`); produce them via `make compile` (`Makefile:49-51`),
  never by editing `==` lines manually.
- **`-U` upgrade flow** is the sanctioned "latest versions" mechanism
  (`Makefile:50-51`, `research.md` Q2/Cross-Cutting). Use it; do not add version
  ranges to `pyproject.toml` — this project deliberately keeps specs out of
  `pyproject.toml` and all version control in lock/pin files
  (`research.md` Cross-Cutting).
- **Validate via the Makefile path**, since that is what CI runs
  (`check.yml:29,32`), even though `CLAUDE.md` favors `just`. Both share the same
  `sync`; the Makefile additionally has `compile` and `audit`
  (`research.md` Cross-Cutting).
- **Keep dual artifacts in step.** Regenerate both `requirements-dev.txt` and
  `uv.lock` together so they don't drift (`research.md` Cross-Cutting, Open Areas).

**Patterns NOT to follow / watch:**
- Don't rely on the Justfile `check` for sign-off — it omits `audit`
  (`Justfile:34`, `research.md` Q6). Use `make check` which includes `pip-audit`.
- Don't assume `uv.lock` is exercised by tests/CI — it isn't consumed by any
  recipe (`research.md` Open Areas). It still must be regenerated for correctness
  and future `uv sync` consumers, but green CI does not prove it is consistent;
  regenerate it explicitly.

## Design Decisions

1. **Upgrade via `make compile` (`uv pip compile -U`), not by adding specifiers** —
   matches the established mechanism (`Makefile:49-51`) and the project's choice to
   keep `pyproject.toml` specifier-free (`research.md` Cross-Cutting). Adding ranges
   would be a scope-creep deviation from house style.
2. **Regenerate `uv.lock` alongside the requirements export** — the Makefile
   `compile` only touches the requirements files, so `uv.lock` needs a separate
   `uv lock --upgrade` step. *Assumption:* `uv lock` against the same
   `pyproject.toml` + GitLab index yields a set consistent with the recompiled
   requirements; verify by inspecting the diff. If `uv lock` is unavailable/auth
   fails against the GitLab index, document and proceed with requirements-only
   regeneration, flagging `uv.lock` drift as a known gap.
3. **Sign off on `make check`, not `just check`** — it is the CI path and the only
   one that includes `pip-audit` (`research.md` Q5/Q6).
4. **Handle `requires-python` floor conflicts by constraining the offending
   package**, not by raising the project floor or dropping the 3.11 matrix leg —
   keeping 3.11 support is a hard requirement (`pyproject.toml:9`,
   `check.yml:19`). *Assumption:* a minimal floor constraint on the single
   offending transitive dep is preferable to broad pins; record any such
   constraint and its reason.
5. **Leave `requirements.txt` header-only** — runtime deps are empty; its compile
   step legitimately produces no pins (`research.md` Q2, Open Areas). Regenerate it
   for header-command consistency but expect an empty body.
6. **Add a Justfile `compile` recipe is OUT of scope** unless trivial — noted as a
   pre-existing gap (`research.md` Q2), not part of this task.

## What We're NOT Doing

- Not adding version specifiers/ranges to `pyproject.toml`.
- Not pinning to specific hand-chosen versions — latest-compatible only.
- Not changing `requires-python`, the Python matrix, or mypi's `python_version`.
- Not reconciling the Justfile/Makefile redundancy or adding `audit` to the
  Justfile (`research.md` Cross-Cutting) — out of scope.
- Not touching GitLab-index config or its authentication
  (`research.md` Open Areas).
- Not removing the self-referential `deadcode` dev dependency
  (`pyproject.toml:29`).

## Open Risks

- **Transitive `requires-python` bumps** breaking the 3.11 leg during
  `uv pip sync` (`research.md` Q5) — caught only by running the 3.11 install +
  check, mirroring CI.
- **GitLab index auth** is not in any tracked file (`research.md` Q4/Open Areas);
  `compile`/`lock` may fail or silently fall back without credentials. Needs a
  working token in the environment.
- **`uv.lock` regeneration is unencoded** (no recipe runs `uv lock`); the exact
  command must be chosen and may surface resolution differences vs. the
  requirements export.
- **Coverage gate (≥ 95%)** or stricter lint/type behavior in newer `ruff`/`mypy`
  could fail after upgrade, requiring small code fixes — but those should be
  surgical and confined to what the upgrade breaks.
- **CI runs only on push/PR to `main`** (`check.yml:3-7`); local multi-version
  validation is the only pre-merge signal across 3.12–3.14.
